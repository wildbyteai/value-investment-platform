# 全文检索平台调整为 Elasticsearch

2026-10-07。状态：用户已确认方案调整；组件接入与生产部署尚未执行。

## 决策与依据

按用户明确要求，将后续全文检索平台由 OpenSearch 调整为 Elasticsearch。业务能力仍包括证券代码/名称精确查询、公告与研究资料全文检索、权限过滤、证据回查及可重建索引。选择依据是统一使用 Elasticsearch 的全文检索与分析生态，并保留同平台向量检索的扩展路径；不是已经证明它比旧候选更快或更便宜。

事实、身份、来源权利、研究历史、评分及策略仍由 PostgreSQL 保存。搜索索引不成为事实或权限真源。03/04/07/08/09/13/17/19及当前报告同步采用本决策；0001与研究历史保留原始选择，检索产品选择以本文件覆盖其对应段落。

## 语义能力与成本

全文搜索为既定能力，语义召回为效果验证后启用的增强。实施时优先评估 Elasticsearch 的向量能力；pgvector 保留为复用 PostgreSQL 的替代候选，不默认同时部署两套向量索引。自然语言检索启用语义时保留混合召回与质量验收，语义无增益则关闭；精确检索始终优先。

官方默认发行物采用 Elastic License 2.0，部分免费源码提供 AGPLv3/SSPL/ELv2 选项，不能沿用旧候选 Apache-2.0 口径。自托管 Basic 基础功能可免费使用，托管、商业支持、进阶能力及运行资源另计；具体发行版本、插件、融合排序与权限特性的订阅要求需在实施时核对。应用对外提供研究界面，与直接对外提供 Elasticsearch 托管服务分别核对许可。

## 影响及验收

变化涉及搜索适配器、索引映射、中文分词、部署配置与预算，暂不改业务计算、数据库或当前运行环境。无已部署搜索集群，因此本次没有迁移现有索引。后续实施仍按 R-02/W-03 和07的检索门禁验证精确命中、证据召回、排序质量、撤权与无泄漏、延迟及重建。未经验证不称检索已交付；不削减原验收标准。
