# 前端按四个业务菜单重组（R4）

状态：proposed（PR 评审中），2026-10-07。

## 背景

原界面 7 个菜单（今日概览、公司研究、研究快照、资讯与研判、策略候选池、我的工作台、系统支持）按开发阶段排列，看不出“资讯 → 公司 → 策略 → 告警”的主线；R3/R5/R6 新增的击球区、资讯雷达、告警和后台配置没有入口。

## 决定

1. 左侧导航只保留五项：**资讯雷达 / 公司档案 / 策略（击球区） / 监控告警 / 后台设置**；每项下用分页签承载具体页面，原有研究页面原样复用：
   - 资讯雷达：事件与关联（新）、原始资料与研判（原“资讯与研判”）
   - 公司档案：公司（原“公司研究”，顶部新增击球区状态与关联资讯）、今日概览、研究快照、我的自选与笔记
   - 策略：击球区看板（新）、策略规则（原“策略候选池”）
   - 监控告警：我的通知（未读数显示在菜单上）、全部告警、通知设置
   - 后台设置：数据源、资讯源与导入（Excel 上传、RSS 登记）、模型配置（DeepSeek 默认，可选通义千问/Kimi/智谱/OpenAI 预设）、告警发送、后台任务（原“系统支持”）
2. 分页签按权限显示（例：模型配置只给系统管理员，资讯确认只给研究员/质量纠正角色）。默认首页为“资讯雷达 · 事件与关联”。
3. 新视图在 `frontend/src/mainline.tsx`，各自读取数据；`app.tsx` 只负责导航与旧页面。
4. 构建产物仍提交在 `backend/static`（后端直接托管），esbuild 改为输出 UTF-8；CI 新增 `frontend-build`：类型检查、构建，并校验提交的产物与源码一致。

## 不做

不更换前端技术栈；不引入路由库；不改旧页面内部逻辑与文案；不实现正式登录（仍为本地开发身份）。浏览器端视觉验收未在本 PR 内运行（沙箱无可用浏览器），需在本机打开核对。

## 验证

`tests/test_r4_ui_contract.py`：产物含五个菜单；新视图调用的每个 API 都已注册；各角色打开对应页面所需接口均返回 200；首页可访问。全量后端测试通过；`npm run build`（含 tsc）通过。
