# 监控告警：只处理落进击球区的球，站内 + 邮件（R6）

状态：proposed（PR 评审中），2026-10-07。

## 背景

ADR 0005 定下渠道为邮件 + 站内、触发条件为进出击球区与区内/边角球的硬风险/重大负面事件，但当时“通知仍后置”。用户 2026-10-07 要求 R3–R6 一次做完，并指定发件人先用 admin@bytewatcher.xyz、后续可改。本 ADR 把告警从“后置”改为“已实现”，收件人规则一并定下初版。

## 决定

1. **球的来源**（`app/domains/monitoring/service.py`，数字在 `config/alerts-v1.json`）：
   - 击球区变化：每次扫描对比上次的区域（`strike_zone_state`）。进入甜区、离开甜区、甜区/边角球因已确认硬风险被否决出区，各发一条。第一次观察为静默基线（与策略 `initial_baseline_notify=false` 一致）。
   - 资讯击球：研究员**确认**的资讯关联，关联度 ≥ 0.50 且 |影响分| ≥ 0.30，且该公司证券此刻在甜区；或影响分 ≤ −0.50 且在边角球。区外的球、边角球的一般消息只留在资讯雷达，不告警。A/H 按证券分别判断。
2. **幂等**：每条告警有去重键（同一关联×证券只发一次；区域变化按证券×日）。
3. **收件人**：工作区内研究员、策略经理、系统管理员（可在配置里改）。站内通知默认开启；邮件需本人在通知设置填写邮箱。
4. **投递**：站内即时可见（未读数、单条/全部已读）。邮件由 `deliver_emails` 发送，SMTP 来自环境变量，发件人 `价投宝 <admin@bytewatcher.xyz>`（`VIP_ALERT_SENDER` 可覆盖）；失败重试至多 5 次；未配置 SMTP 时记为“已跳过”，不会在配置后补发旧告警。
5. **运行**：`python -m app.jobs alerts`（cron）；确认资讯关联时立即检查该球；`POST /api/alerts/scan` 手动运行；后台 › 告警发送 查看发件配置、收件人与投递统计。
6. 不改 `change_record` 与其 `delivery_count`（策略状态机的事实与金标测试保持原样）；告警读取的是击球区分类，不是封存评估。

## 不做

不接飞书/短信/企业微信；不发交易指令；不对区外的球告警；不为历史数据补发告警。

## 验证

`tests/test_r6_alerts.py` 8 项：默认发件人、基线静默 + 进入/离开甜区、邮件失败重试/发送/不重发、未配置 SMTP 跳过与去重、资讯只在甜区告警（弱影响、区外不告警、重复扫描不重复）、边角球重大利空与硬风险否决、站内收件箱/已读/权限、真实击球区服务扫描接口。全量 300 项通过。
