# 0005 产品主线四层与击球区

2026-10-07。状态：**已确认**（用户 2026-10-07 确认）；其中击球区“安全边际”阈值**待确认**。本决策只改文档，未改代码、配置或业务数字；相关功能均未实现。

## 背景

现有设计（docs/01…20）覆盖面广、细节多，但缺少一条让人一眼看懂“系统为谁、每天做什么”的主线；界面是七个平铺页面（docs/18 §3.1），资讯输入仍靠人工定时任务生成的 6 份 Excel。用户在 2026-10-07 用自己的话重新讲清了底层逻辑，并要求按此重构。

## 决定

1. **四层主线**：①新闻资讯（关联公司、关联度、影响分）→ ②公司（商业模式、财报、关联资讯、打分）→ ③价值投资策略逻辑 → ④击球区（只处理落在击球区内的“球”，并监控告警）。
2. **四个菜单 + 设置**：资讯雷达 / 公司档案 / 策略（划击球区）/ 监控告警 / 设置（数据源、后台任务、账号权限）。封存、修订、冻结清单、hash 等保留为后台保证，不进入日常界面术语。
3. **击球区三条件**（缺一不可）：(a) 能力圈——研究员维护的行业/公司名单 + 评分覆盖度 ≥0.8；(b) 好生意——复用 config/strategy-standard-v1.json 已发布的质量与财务门槛、无已确认硬风险；(c) 好价格——v1 用现有证券估值分门槛替代，后续以安全边际 =(内在价值−价格)/内在价值 衡量，目标阈值（例如 ≥30%）**待确认**。分为甜区（沿用连续 2 个 FINAL 时段确认后入池）、边角球（观察名单，只盯价格）、区外（只记录不告警）；A/H 分开判断，硬风险立即否决。
4. **告警**：仍然后置；将来渠道为**邮件 + 站内**；只在进入击球区、离开击球区、区内或边角球公司出现硬风险/重大负面事件时触发；change_record 仍是事实来源。
5. **数据模型以代码为真源**：当前代码中的 35 张表为准，design/database-catalog.json 在 R3 对齐到代码（用户未提出异议）。

详细说明见 [docs/00 产品主线](../00-product-mainline.md)。
