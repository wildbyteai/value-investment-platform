## 1. 重构背景与核心设计原则

### 1.1 现状痛点
1. **术语系统内部化、防御色彩重**：页面充斥着开发内部状态与状态机黑话（如“有效维度覆盖 0%”、“未有有效资料”、“正式收盘最终性尚未核验”、“If-Match-Generation”、“未正式封存或产生策略状态变化”），普通研究员与投资者无法直观理解当前状态到底是系统故障、缺少数据，还是正常研究流程。
2. **信息层级混乱、未格式化 JSON 裸露**：主视线内大量出现 `<details><summary>查看依据与诊断</summary><pre>{JSON...}</pre></details>`，把本应收拢于底层技术诊断的数据直接倾倒在业务首屏，导致界面形同 API 调试面板。
3. **关键操作缺乏指引与容错**：
   - 模板编辑要求用户手写 JSON patch 数组（如 `[{"dimension":"business_model",...}]`）；当前action会捕获解析错误，但缺少字段附近的业务说明和修正指引，不能把它写成未捕获异常或必然崩溃；
   - 档位与影响修改使用裸单行文本框输入数字（`0-4` 或 `-1到1`），缺乏业务档位说明与辅助选择器；
   - 关注按钮缺乏“已关注”状态切换与取消关注功能；
   - 缺少对 A/H 分离估值、财务口径、数据缺口的建设性业务指引。

以上是源码和设计提出的待解决问题，不是本轮目标用户测试结果。`If-Match-Generation`目前属于接口合同，不应未经实际页面核查就声称它出现在业务首屏；JSON已折叠但仍占页面空间，重构目标是统一诊断入口。

### 1.2 四大重构原则
1. **业务主权原则（Business-First）**：用“投资研究者的工作流”替代“后台服务的执行流水”。页面必须首先回答投资者的四个核心问题：**“公司发生什么、依据是什么、能不能做决策、下一步缺什么”**。
2. **渐进披露原则（Progressive Disclosure）**：首屏只放业务结论与核心数据；详细拆解放在二层结构；原始 JSON、请求元数据、系统哈希（Hash）、任务队列表等全部收拢至底层的“技术诊断”抽屉中，不干扰日常研读。
3. **防御式操作与容错选择（Affordance & Safe Controls）**：禁止让普通研究员手写代码或原始 JSON。离散档位使用语义化下拉选择器；浮点门槛使用滑块或带边界步进器；复杂配置提供可视化表单与范例切换。
4. **建设性未知与状态透明（Constructive UNKNOWN）**：数据不足时保持诚实（不给假分），同时列出具体缺口及可用下一步。未知、明确不符合、暂未正式评估、停牌、风险排除分别表达；未知不写成“不满足准入”或“未入选”。尚未实现的补齐功能只说明依赖，不给不能完成的操作按钮。

## 2. 全局术语与文案对照规范字典

| 模块 / 语境 | 现状文案（工程/防御视角） | 用户难懂原因 | 重构后文案（投资研究业务视角） | 设计与业务意图 |
|---|---|---|---|---|
| **全局状态** | `当前仅使用真实来源。真实日线与财务指标已接入；标准口径依据不足时，评分保持未知。` | 警示重复，容易误以为系统出错 | `真实资料研究预览。已有资料可阅读；评分所需依据仍待补齐。` | 简明表达可做与待做事项，具体缺口放公司内。 |

| **A股报价** | `真实日线收盘 {价格} · 未复权；正式收盘最终性尚未核验` | 正式收盘最终性是工程术语 | `参考日线价：{价格} {币种} · {交易日}（未复权）。尚未核验为正式策略评估用价。` | 本系统不交易、不调仓或结算，避免“调仓结算价”措辞。 |

| **运行状态** | `核对策略：有待补依据 · 逐证券计算草稿规则；缺数为UNKNOWN，未正式封存或应用` | 工程与业务语言混用 | `策略筛选：待评估（缺少关键依据）。本次仅为研究预览，不改变正式入选状态。` | 正式封存是独立待实现流程，不把未知变成否定。 |
| **判断覆盖** | `完整新档位（0–4）` / `完整新影响（−1到1）` | 裸数字缺少选择依据 | `评级：选择本评价项的0–4档证据锚点；影响：正向/负向/无净影响 + 强度数值。` | 11个评价项各用config锚点；保留有符号连续数值，不发明四档映射或硬风险。 |

## 3. 七大页面重构详细规格

### 3.1 导航体系重构
将平铺的 7 个 Tab 梳理为“业务研究流”与“管理支撑流”两层：
- **主业务导航（日常研究主路径）**：
  1. **今日概览 (`today`)**：首屏展示监控公司结论摘要、关键缺口与最新动态。
  2. **公司研究 (`companies`)**：核心工作台，A/H 估值并列对比、定性研判进度、资料时间线、财务对比表。
  3. **研究快照 (`research`)**：研究快照生成、固定依据版本核验、历史快照对比。
  4. **资讯与研判 (`news`)**：真实资料阅读（正文/作者历史）、定性评价项及影响判断入口。原`judgments`能力并入此处及公司页，不丢失查看/覆盖/解除功能。
  5. **策略候选池 (`strategy`)**：准入门槛模拟、规则版本查看、状态流转记录。
  6. **我的工作台 (`mine`)**：我的自选列表（支持 A/H 分开关注与取消）、研究笔记。
- **系统支持（底部工具区 / 管理抽屉）**：
  - 数据源状态、任务恢复（Worker Outbox）、本地身份切换、系统技术日志。

##### 关键组件与排版细节：
1. **证券卡片（A/H 对比）**：
   - 明确突出 A/H 独立价格、独立币种、独立估值分的原则；
   - 港股缺行情时以待补状态区分，明确标注“A/H共享企业基本面，估值使用港股本币行情与对应汇率独立测算”；行情就绪后按实际状态显示，不固定为缺数卡片。
2. **经营质量拆解标签页 (Quality Tab)**：
   - 维度、顺序、权重、禁用及自定义项来自当前已发布解析模板；基准配置当前为盈利25%/财务韧性25%/商业模式25%/治理15%/成长10%，只作为核对基线，不是写死的UI数据。行业/企业覆盖后可能不同。
   - 各卡展示当前有效分或“待评估”、缺口、权重与继承来源。财务维度由标准原始科目计算，不用人工档位替代；定性维度展开其评价项及各自证据锚点。
   - 对已有合法判断可查看/覆盖/解除；从空状态首次创建真实研判需要§6的后端依赖。不能用一个总维度档位代替各criterion。
   - “有效依据n/N”仅辅助进度；加权coverage及必需维度要求仍由后端返回。动态扩展不强制限制为五维，缺失、过期、无权访问与不适用分别展示。
3. **技术诊断隔离 (Clean Architecture)**：
   - 移除主视线内的裸 JSON `<pre>` 标签，替换为对象附近的轻量链接`[技术诊断]`，点击后在可访问抽屉中以可读格式展示已有元数据；不暗示已具有完整正式manifest。语法高亮是可选，不为此新增框架；业务原文定位与计算解释仍在业务二层可读。

#### 页面三：资讯与研判 (`news` / 资料与定性研判)
- **资讯列表区**：
  - 每条资料卡片包含：
    - 来源标签：`[维基百科 CC BY-SA 4.0]` / `[BaoStock 免费接口]`
    - 标题与取得时间：明确区分“资讯公布/修订时间”与“系统抓取入库时间”；
    - 摘要内容：2-3 行提炼；
    - 底部操作栏：正文已取得才用`[阅读固定原文]`；只有网址写`[来源入口]`，无入口写“暂无原文入口”。作者历史/外部固定版本/许可按来源实际元数据分别展示；财务原文是提供商响应，不冒称发行人审计财报。无权访问时不泄漏链接、修订或正文。
- **定性判断录入抽屉 (Judgment Drawer)**：
  - 当研究员点击对某维度进行评级时：
    - **评级对象**：锁定当前公司、维度、rubric、criterion与period（如：比亚迪 - 商业模式 - 定价能力 - 对应研究期间）；修改既有slot时不得改其身份。
    - **档位选择器 (Rubric Grade)**：
      - 单选卡片式选择：
        - `[0–4 档] {本criterion对应的config锚点原文}`，锚点唯一来源为`config/rubrics-standard-v1.json`与已发布rubric引用；“未调查/无法确认”是独立未知状态，不当作0档。
        - 0档表示本项证据支持的低档位，不自动成为欺诈/违约/退市等硬风险。硬风险仍走独立证据/政策流程。
    - **证据依据选择**：只从当前有权访问且关联该公司的固定修订选择，记录支持/反驳证据及段落/单元定位；仅勾选hash不能证明主张。期间/有效期、依据类别和置信度语义沿用11/12。百科或提供商指标不自动满足发行人原始披露门。
    - **研究员研判理由 (必填 textarea)**：`请写下支持该评级的核心事实与逻辑...`
    - **操作按钮**：`[保存研判]` / `[取消]`，服务端确认生效后再显示“研判已生效”；评分是否已刷新另行说明。权限/证据/过期/并发失败保留输入，不能承诺点击即完成全部评分。首次创建、理由及完整证据写入接口尚待补齐。

- **影响判断**：保留正向/负向/无净影响与0–1强度，派生有符号-1到1十进制字符串；控件支持已有值精确回显，不截断、不强制四档映射。confidence不是强度；零不是未知。数值、证据、事实身份与半衰期等合同不变，保存仍由后端校验。

#### 页面四：研究快照与测算 (`research` / 证据版本与快照)
- **首屏操作栏**：

## 4. 关键交互流程与容错设计

### 4.1 自选股状态机与交互闭环
- **前端状态缓存**：在前端维护 `Set<securityId>`，初次加载拉取用户已有自选列表。
  - Set必须随身份/工作区切换清空重取，不能共享上一人的状态；首次加载失败显示未知，不默认为未关注。
- **按钮渲染逻辑**：
  - 若 `hasWatch(securityId)` 为 false：渲染边框按钮 `[+ 关注此证券]`，点击发送 `POST /api/me/watchlist/{security_id}`；
  - 若 `hasWatch(securityId)` 为 true：渲染浅蓝高亮按钮 `[✓ 已关注 (点击移除)]`，点击发送 `DELETE /api/me/watchlist/{security_id}`；
  - 请求中状态：显示微型转圈动画并禁用，避免重复点击。
  - 成功后按服务器结果及回读更新；失败保留原关注状态，给重试入口。当前GET只返回ticker/market，无security_id且无DELETE端点，须先补接口，不假设现已支持。

### 4.2 模板维护的可视化表单改造
- **现状**：直接放一个包含 JSON patch 的 textarea。
- **改造方案**：
  - 主视图提供图形化调整界面：
    1. **维度权重微调**：依据有效模板动态生成控件，显示原值、草稿值、总和与来源；不自动调整其他权重。总和不为100%提示差额并禁用发布，后端仍校验；必需维度不能禁用，自定义维度沿用注册合同。
    2. **事件政策开关**：每个维度提供复选框 `[✓ 允许突发新闻事件修正基础分]`；
    3. **按钮**：`[预览模板差异]` -> 展示已发布/草稿权重和政策差异。当前preview只返回resolved与hash，没有模拟评分，不能绘制虚构的评分差异柱；实际重算属于新增后端依赖。
  - **高级选项（折叠手风琴面板）**：
    - `[展开高级配置]`：仅对有template.edit权限者显示JSON编辑器；语法错误就地解释并保留输入，不能仅凭前端解析声称字段/身份/合同合法。图形与高级草稿双向同步，不能静默丢失高级政策；发布另需template.publish权限、版本CAS和服务端校验。

## 6. 实施切片与验收标准对照

按照业务价值与技术依赖，分为三个递进落地切片：

```mermaid
flowchart LR
  P1["切片 A: 业务状态与文案"] --> P2["切片 B: 页面布局与诊断分层"]
  P2 --> P3["切片 C: 有界控件与依赖接口闭环"]
```

### 切片 A：文案与业务状态表达（不改计算合同）
- **交付内容**：业务区按第2节表达，保留后端代码值于诊断区；未知/不通过/尚未正式评估、参考价格/正式价格、字段比较/经营分析、草稿/已发布分别标示。动态渲染行情/权重/规则，不写死示例。
- **验证**：UX18-01…04；从源码与实际回读核对正常、缺数、非法/过期数据及来源不可读。实际普通用户理解仍以T-UX任务验收，不能由开发者通读推定通过。

### 切片 B：页面排版三段式重构与 JSON 隔离（布局与视觉层）
- **交付内容**：
  - 公司研究页改为“概览看板 + A/H 并列卡片 + 四标签深度分析”；
  - 将所有 `<pre>{JSON...}</pre>` 移入底部的“技术诊断与元数据”抽屉中；
  - 增加依据进度（动态`n/N`及独立加权coverage，不称准确率）。
- 诊断入口按对象保留，普通用户仍可看到有权读取的业务依据；折叠不替代服务端权限。今日概览仅聚合已有读接口，不能暗中采集或运行研究。
- **验证**：UX18-05/06/11/12；覆盖桌面/窄屏、键盘、加载/空/部分失败及返回状态。无法浏览/没有实际像素时，只能标记布局已设计，视觉未验证。

### 切片 C：有界输入与交互闭环（按接口依赖分段）
- **交付内容**：
  - 档位与影响修改改为语义化下拉选择器；
  - 模板维护提供图形化权重滑块，折叠高级 JSON 模式；
  - 补齐自选股关注状态切换与取消关注功能。
- 已有判断控件、模板差异可先改；取消关注须完成接口后交付。首次真实研判、估值门槛编辑、评分差异和历史对比单列后端子切片，不塞进“纯前端”验收。
- **验证**：UX18-07…10；有效操作保存回读，非法输入就地提示，403/404/409/422/网络失败保留草稿，服务端仍可拒绝。目标是降低错误并正确恢复，不保证永远不会有422。
