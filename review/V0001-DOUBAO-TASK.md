## 四、工程和数据库

沿用模块化单体：React/TypeScript + FastAPI/Pydantic + SQLAlchemy/Alembic + PostgreSQL，任务使用 PG ledger/outbox 与项目专用 worker。保持 API/生成 TypeScript 客户端同源；前端不另写评分和策略算法。按切片落实必要表，不一次建立全部 79 张设计表，不擅自增加微服务、第二套调度器、搜索平台或框架。

优先目标线：Python 3.12、PostgreSQL 17、Node 24 LTS、pnpm 10、Redis 7.4/Celery 5。核验实际可用版本、兼容性和锁文件；必要的运行线调整记录理由与影响，不改业务合同。

交接探查显示本机当时没有 docker，已有 uv、psql、brew，系统 Python 3.14.6、Node 26.3.1；这些信息可能变化，重新检查。缺 Docker 时可使用项目专用的原生本地 PostgreSQL/Redis，交付 Compose 配置作为另一启动方式。不能因环境困难偷偷用 SQLite 代替 PG，不能修改全机默认服务来迁就项目。

数据库操作前验证实际服务器进程、版本、数据目录、端口/socket、数据库、角色、用途和数据性质。不得只看 localhost 就认定项目隔离。优先创建新的项目专用集群或经确认的独立库，专用端口与账号，仅本地监听；不碰其他项目数据库。

建议分别设置 `vip_v0001_test` 和 `vip_v0001_local`：前者只放合成测试夹具，可按任务重建；后者放本次获许可公开真实资料，本提示词明确授权在该新建隔离库内导入、追加修订和必要迁移。真实库不用于破坏性测试、不默认重置、不删除有效原始输入；迁移前保存可恢复备份。必要恢复演练在合成库或其新建副本中进行。

未能核实分类或发现既有业务数据时，相关目标保持只读，改建新的项目隔离目标继续；不要猜测。凭证只放本地忽略文件，日志和报告不泄露密码。测试/真实导入的数据库写操作不能仅因为同在本机就混用授权。

## 五、连续切片与业务闭环

按 docs/17 的 W-08.1…8 推进，保留 docs/13 完整出口，真实接入增加一个有界任务及其证据：

2. 资料先可读：原创合成 Excel/直接资料导入，报告→条目→来源→原文血缘；日期精度、部分失败与重试，摘要不等待评分。资讯按时间线阅读，原文状态明确。
3. 公司研究：歧义/no_link/多公司，关联自动政策、事件与经济事实归并；新闻和有效事件分开。重复资料不造成重复影响。
4. 有效判断：影响/rubric/风险、人工替换与解除、冲突保留输入、证据定位、H 挂牌风险与公司风险区分、依赖重算。
5. 模板与解释：base→industry→company，完整维度和 x_customer_retention；经营基础/事件贡献、A/H 分开估值、缺数据、历史依据。
6. 策略到变化：模拟与人发布、冻结输入、相邻 FINAL、ENTER/UNKNOWN/恢复/EXIT/RISK；版本/日期/原因一致，已发布历史不可覆写。
7. 协作与恢复：自选、笔记、失败洞、ledger 恢复、重复投递、旧 generation 拒绝、历史纠错及既定合成备份/撤权恢复。
8. UI 与全链收口：连接真实后端，浏览器实际完成连续用户任务，修复影响业务和理解的问题。
9. 真实源最小接入：合成主路径及相关权限/恢复门通过后启用选定源，完成真实请求→本地落库→摘要/原文→正确公司时间线→证据回读；有足够可信数据再运行真实评分/策略。测试模式、真实资料模式和 mock 分析状态明确区分。

核心页面：今日变化、新闻资讯时间线、公司工作区、原文阅读、判断与人工覆盖、模板解析、策略模拟/发布、来源/任务恢复、角色管理、自选/笔记。用真实公司名称帮助理解，但合成示例明显标注“演示”；真实资料标出处和取得时间。

文案用研究人员能理解的中文，例如“今天有哪些新消息”“为什么分数变了”“还缺哪些资料”“本次修改已生效，评分正在更新”。内部 ID、generation、manifest 等留在诊断或证据页。覆盖加载、空、部分失败、无权、冲突、等待计算、UNKNOWN 和历史/当前版本区别，避免用过期成功结果假装新计算完成。
